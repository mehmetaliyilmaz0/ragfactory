# SDK refresh research (2026-10-20)

## Scope and confidence

This is a package and source compatibility review for the generated LangChain and LlamaIndex pipelines. PyPI release pages and official project docs were checked on 2026-10-20. Suggested ranges below follow stable release lines and the projects' own dependency metadata; they are candidate resolver constraints, not a claim that every combination of optional integrations has already been runtime-tested. The test suite and an install matrix still need to validate the combinations actually generated by this repository.

### Migration decisions and limitations

- Both generated frameworks include `python-dotenv>=1,<2`, because generated entrypoints load `.env` files.
- LlamaIndex hybrid retrieval is supported only with Qdrant. Sparse+dense indexing must be enabled during ingestion, with `fastembed_sparse_model="Qdrant/bm25"`; other vector stores should be rejected during generation rather than silently receiving an unsupported hybrid retriever. The LlamaIndex Qdrant adapter 0.10.4 defaults to relative-score fusion. For `hybrid_rrf`, generated Qdrant configuration supplies an explicit fusion callback using the configured smoothing constant; `hybrid_weighted` uses the adapter's alpha-weighted relative-score fusion. This differs from LangChain's weighted reciprocal-rank implementation for the `hybrid_weighted` strategy.
- LangChain BM25 uses the actual final ingestion chunks. The generated ingestion pipeline writes adjacent UTF-8 `chunks.json` records containing `page_content` and `metadata`; the retriever checks for a non-empty corpus before constructing BM25.
- `langchain-experimental` 0.4.2 includes `SemanticChunker`, but PyPI marks the package sunset/archived (June 2026). Treat LangChain semantic chunking as a maintenance risk. LlamaIndex's `SemanticSplitterNodeParser` is in core and does not need sentence-transformers for this implementation.
- Do not infer that an adapter accepts every provider model ID from a `model: str` constructor. LangChain's OpenAI adapter accepts arbitrary model strings. LlamaIndex's OpenAI and Anthropic adapters use metadata registries in addition to accepting constructor values; official issues show unsupported model IDs can fail with `ValueError: Unknown model` until their registries are updated. Verify each selected LlamaIndex default against that exact integration release. [LangChain ChatOpenAI source](https://github.com/langchain-ai/langchain/blob/master/libs/partners/openai/langchain_openai/chat_models/base.py), [LlamaIndex OpenAI metadata issue](https://github.com/run-llama/llama_index/issues/21155), [LlamaIndex Anthropic metadata issue](https://github.com/run-llama/llama_index/issues/23222).
- These are compatible range candidates, not a claim that every optional integration Cartesian product is tested. Resolver checks are required for generated profiles, especially local Torch/FlagEmbedding/Ragatouille/Docling stacks.

**Caution:** PyPI's current project pages establish that the cited releases exist and their `Requires-Python`; they do not by themselves prove cross-package solver compatibility or that template code runs. The project's `versions.py` design says ranges are manually tested, so keep this matrix provisional until generated dependency combinations are resolver-checked and template imports are exercised.
